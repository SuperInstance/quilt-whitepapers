# quilt-whitepapers

> The SuperInstance fleet's experimental record, stated plainly. Each paper
> says how a system actually works, what the receipts show, what it leaves
> behind for the next builder, and where it honestly fails.

**The series doctrine** (from the founder, layer G): document heavily; be
frank; the tools don't have to be better-faster-cheaper — they must leave
the **bones of a solution to another problem**, because building the jig
makes the next time cheaper. *We are not saving the decision tree; we are
shaping the environment that cultivated the right decision.*

## How to read

Each paper follows the same skeleton: **Claim → Mechanism (how it actually
works) → Evidence (receipted numbers, repo links) → Bones (what it leaves
behind) → Limits (where it honestly fails)**. The numbers are copied from
the repos' own receipts files, not from memory; where a claim has no
receipt, the paper says so.
